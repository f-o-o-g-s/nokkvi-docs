Nokkvi is a client for the [Navidrome](https://www.navidrome.org/) music server. To use it, you'll need a running Navidrome instance.

If your server hosts more than one library (music folder), see [Multi-library filter](/guides/multi-library/) for how Nokkvi scopes the browse views.

## Server Connection

When you first launch Nokkvi, you'll be greeted with a login screen.

1. **Server URL**: Enter the full URL of your server, including the protocol (e.g., `https://music.yourdomain.com`). If your server isn't behind a reverse proxy on 443/80, include the port — Navidrome's default is 4533, e.g. `http://navidrome.local:4533`. You can also type just the host (e.g. `navidrome.local:4533`) — Nokkvi tries HTTPS first and falls back to HTTP only for local/LAN addresses; an explicit `http://` to a remote server shows a cleartext-credentials warning.
2. **Username**: Your Navidrome username.
3. **Password**: Your Navidrome password.

<Aside type="note" title="Server version and smart playlists">
  Most of Nokkvi works against any recent Navidrome. The one feature with a hard version gate is [smart playlists](/guides/smart-playlists/), which needs **Navidrome 0.61+** — on older servers those controls simply don't appear. A few advanced rule fields need 0.62, 0.63, or 0.64 — and 0.64 also unlocks a per-playlist refresh delay. Nokkvi flags any rule your server is too old to evaluate. See the [version floors](/reference/smart-playlist-rules/#navidrome-version-floors) for the details.
</Aside>

## Persistent Sessions

You type your password once. Nokkvi signs in with it and keeps a session instead, so later launches skip the login screen. Your password is never written to disk.

What's saved, and where:

- **`config.toml`**: the server URL and your username. Nokkvi resumes a saved session only while these still name the server and user it belongs to; change either one and you'll get the login screen.
- **`app.redb`** (`~/.local/state/nokkvi/`): the session. That's a JWT for Navidrome's own API (browsing, playlists) plus a second credential for the Subsonic API, which streaming, artwork, ratings and scrobbles go through.

Each time Nokkvi uses Navidrome's own API, Navidrome hands back a fresh JWT. Nokkvi keeps using the newest one and saves a fresh copy before the saved one gets close to running out, so a session you keep using doesn't expire. To switch servers or users, go to **Settings → General → Account** and select **Logout**.

### The Subsonic credential

On today's Navidrome releases (up to 0.64.x) the Subsonic credential is the token and salt pair that Navidrome returns at login. That pair only works because Navidrome keeps your password stored in a form it can decrypt.

Navidrome's development version adds OpenSubsonic API keys as an alternative. They aren't in a release yet, but Nokkvi already supports them. On a server that offers API keys, Nokkvi:

- creates its own key and registers it on a player named **nokkvi (*your computer's name*)** in Navidrome, then uses that key instead of the token pair;
- puts a fresh key on that player at every password login, which retires the old one;
- moves an existing session over to a key in the background the first time it starts on a server that offers them, so you don't have to log in again;
- removes the key when you select **Logout**. If the server can't be reached then, Nokkvi warns you, and you can remove the key in Navidrome yourself.

If a key can't be set up, Nokkvi carries on with the token pair. Because the key belongs to that player, the player's transcoding, bitrate and scrobbling settings in Navidrome apply to Nokkvi.

<Aside type="caution" title="A password change doesn't revoke an API key">
  Changing your Navidrome password ends Nokkvi's JWT, but a key keeps working until it's replaced or removed. If you lose a device that was signed in, open **Players & API keys** in Navidrome's web UI and delete that device's **nokkvi (…)** player.
</Aside>

### When a session ends

At startup Nokkvi checks the saved session with the server before loading anything else. If the server refuses it, you're back at the login screen with "Session expired. Please log in again." That happens when the session has expired, or after a password change on Navidrome 0.64.0 and newer (older versions keep sessions through a password change). If the server can't be reached yet, for example when Nokkvi autostarts before the network is up, it resumes anyway.

Navidrome limits sign-ins: its login allows 5 attempts from one address in 20 seconds, and since 0.64.1 its Subsonic API also blocks a user from one address after 5 failed attempts within 20 seconds. If that block is still running when you log in, for example right after a password change while another device keeps trying the old one, Nokkvi waits it out (up to 30 seconds) instead of failing.

By default, Navidrome sessions expire after 48 hours without use. The `SessionTimeout` setting in the recommended config below extends this.

## Recommended navidrome.toml for Nokkvi

Below is a reference configuration tuned for use with Nokkvi. Artwork-specific settings (`ImageCacheSize`, `EnableWebPEncoding`) are covered in [Artwork & Performance](/guides/artwork/#navidrome-server-settings).

### Session Timeout

`SessionTimeout` is documented in Navidrome's [configuration options reference](https://www.navidrome.org/docs/usage/configuration/options/#advanced-configuration) (under Advanced configuration).

```toml
SessionTimeout = "8760h"
```

<Aside type="caution" title="Security Tradeoff">
  A long session timeout means a compromised device stays authenticated longer. Use a duration that fits your security needs.
</Aside>

### Scrobbling

Nokkvi submits scrobbles through Navidrome's Subsonic API — Navidrome handles forwarding them to Last.fm and ListenBrainz. Both services need to be configured on the server side for scrobbling to work end-to-end. Client-side toggles live under [`scrobbling_enabled`](/reference/config/#scrobbling) and [`scrobble_threshold`](/reference/config/#scrobbling). Internet-radio streams are the exception — they scrobble directly from Nokkvi to ListenBrainz/Last.fm, bypassing the server; see [Radio → Scrobbling](/guides/radio/#scrobbling).

Nokkvi — not the server — decides when a play counts. It submits a scrobble once your *actual listening time* reaches **`scrobble_threshold` of the track length, or 4 minutes, whichever comes first**. Listening time is real playback: seeking ahead or pausing doesn't count toward it.

When that point is reached, Nokkvi tells Navidrome once, and Navidrome trusts it — it increments the track's **play count** (and the album's and artist's) and forwards the scrobble to Last.fm/ListenBrainz in the same step. There's no second threshold on the server. If a track never reaches that point (you skip it early, or play less than the threshold of a track shorter than 4 minutes), Nokkvi sends nothing: no play count is recorded and nothing reaches Last.fm. The "now playing" updates sent during playback never count as plays.

<Aside type="note" title="A high threshold won't hold back long tracks">
  The 4-minute arm is fixed and independent of `scrobble_threshold`. Set the threshold to `0.90` and a 20-minute mix still scrobbles after 4 minutes of listening — not 18. The threshold only governs tracks short enough that its percentage is reached before the 4-minute mark.
</Aside>

To get Last.fm API credentials, create an API account at [last.fm/api](https://www.last.fm/api/account/create). For ListenBrainz, generate a token from your [profile settings](https://listenbrainz.org/profile/).

```toml
EnableExternalServices = true

[LastFM]
Enabled = true
ApiKey = "your_lastfm_api_key"
Secret = "your_lastfm_secret"

[ListenBrainz]
Enabled = true
Token = "your_listenbrainz_token"
```
